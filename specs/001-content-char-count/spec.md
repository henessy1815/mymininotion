# Feature Specification: 내용 글자 수 표시

**Feature Branch**: `001-content-char-count`

**Created**: 2026-10-01

**Status**: Draft

**Input**: User description: "내용입력칸 아래에다가 내용을 입력하면 글자 수 계산하는 기능을 만들거야."

## Clarifications

### Session 2026-10-01

- Q: 글자 수를 공백 포함 수 하나만 보여 줄까요, 아니면 공백 제외 수도 함께 보여 줄까요? → A: 두 값을 한 줄에 함께 표시한다 (예: `공백 포함 1,234자 · 공백 제외 1,050자`).
- Q: 내용이 길어서 입력칸 아래 글자 수가 화면 밖으로 밀려날 때, 글자 수를 어디에 보여 줄까요? → A: 내용 바로 아래에만 둔다. 화면 하단·헤더에 고정하지 않으며, 긴 글이면 스크롤해서 확인한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 입력하는 동안 글자 수 확인 (Priority: P1)

사용자는 글 상세 화면에서 내용을 쓰는 동안, 내용 입력칸 바로 아래에서 지금까지 쓴 글자 수를
확인한다. 글자를 입력하거나 지우면 숫자가 즉시 바뀌므로, 분량 제한이 있는 글(보고서 요약,
자기소개, 게시글 초안 등)을 다른 도구로 옮기지 않고 여기서 길이를 맞출 수 있다.

**Why this priority**: 요청된 기능의 핵심이며, 이것만으로도 "분량을 확인하려고 다른 글자 수 세기
사이트에 붙여 넣는" 불편이 사라진다.

**Independent Test**: 글 상세 화면에서 내용 입력칸에 글자를 입력·삭제하고, 입력칸 아래 공백 포함 글자 수가
매번 정확한 숫자로 바뀌는지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 내용이 비어 있는 글을 열었을 때, **When** 화면이 표시되면, **Then** 내용 입력칸 아래에 `공백 포함 0자`가 보인다.
2. **Given** 내용이 비어 있는 글, **When** `안녕하세요`를 입력하면, **Then** 표시가 `공백 포함 5자`로 바뀐다.
3. **Given** 내용이 `안녕하세요`인 글, **When** 마지막 글자 하나를 지우면, **Then** 표시가 `공백 포함 4자`로 바뀐다.
4. **Given** 내용이 이미 있는 글(예: 1,234자), **When** 그 글을 열면, **Then** 입력하기 전부터 `공백 포함 1,234자`가 보인다.
5. **Given** 내용이 `가 나`(공백 포함 3글자)인 글, **When** 화면이 표시되면, **Then** 표시는 `공백 포함 3자`다 (공백도 1자로 센다).

---

### User Story 2 - 공백 제외 글자 수 함께 확인 (Priority: P2)

사용자는 공백을 포함한 글자 수와 함께 공백을 뺀 글자 수도 확인한다. 분량 기준이 "공백 제외"로
주어지는 경우(국내 지원서·과제 등에서 흔함)에도 별도 계산 없이 바로 판단할 수 있다.

**Why this priority**: P1만으로도 대부분의 분량 확인이 가능하지만, 한국어 글쓰기에서는 공백 제외
기준이 자주 쓰여 함께 보여 주면 가치가 크다.

**Independent Test**: 공백과 줄바꿈이 섞인 내용을 입력하고, 공백 포함/제외 두 숫자가 각각 정확한지
확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 내용이 `가 나`인 글, **When** 화면이 표시되면, **Then** 한 줄에 `공백 포함 3자 · 공백 제외 2자`가 보인다.
2. **Given** 내용이 `가`, 줄바꿈, `나`인 글, **When** 화면이 표시되면, **Then** `공백 포함 3자 · 공백 제외 2자`가 보인다 (줄바꿈은 공백으로 취급한다).
3. **Given** 내용이 비어 있는 글, **When** 화면이 표시되면, **Then** `공백 포함 0자 · 공백 제외 0자`가 보인다.

---

### Edge Cases

- **한글 조합 중**: 한글을 조합하는 동안에도 화면에 보이는 내용 기준으로 센다. 예: `한`을 조합 중이면 `1자`.
- **이모지·결합 문자**: 화면에서 한 글자로 보이는 단위를 1자로 센다. 예: `👍`는 1자, 피부색이 붙은 `👍🏽`도 1자, 가족 이모지 `👨‍👩‍👧`도 1자.
- **공백만 입력**: 공백 3칸만 있으면 공백 포함 `3자`, 공백 제외 `0자`다.
- **긴 내용**: 수만 자 분량의 내용에서도 입력이 눈에 띄게 느려지지 않으며, 숫자는 천 단위 구분 기호로 표시한다 (예: `12,345자`).
- **붙여넣기·잘라내기·실행 취소**: 키보드 입력이 아닌 방식으로 내용이 바뀌어도 즉시 반영된다.
- **저장 실패 상태**: 저장이 실패해도 글자 수는 화면에 보이는 현재 내용 기준으로 계속 정확하게 표시된다.
- **제목**: 제목 입력은 글자 수에 포함하지 않는다.
- **긴 글**: 내용이 화면보다 길면 글자 수 표시도 내용과 함께 아래로 밀려나며, 사용자는 내용 끝까지 스크롤해 확인한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 글 상세 화면의 내용 입력칸 바로 아래에 현재 내용의 글자 수를 표시해야 한다(MUST) 표시는 내용 바로 다음 위치에만 두며, 화면 하단이나 헤더에 고정하지 않는다(MUST NOT).
- **FR-002**: 글자 수는 내용이 바뀔 때마다(입력, 삭제, 붙여넣기, 잘라내기, 실행 취소 등) 자동 저장을 기다리지 않고 즉시 갱신되어야 한다(MUST).
- **FR-003**: 기본 글자 수는 공백·줄바꿈을 포함해 센다(MUST).
- **FR-004**: 시스템은 공백 제외 글자 수(공백·탭·줄바꿈 등 모든 공백 문자를 뺀 수)도 공백 포함 수와 같은 줄에 함께 표시해야 한다(MUST, P2). 표시 형식은 `공백 포함 N자 · 공백 제외 M자`다.
- **FR-005**: 글자 하나는 사용자가 화면에서 한 글자로 인식하는 단위로 센다(MUST). 한글 음절 1개, 영문자 1개, 이모지 1개(결합 이모지 포함)는 각각 1자다.
- **FR-006**: 글자 수는 제목을 제외한 내용만 대상으로 한다(MUST).
- **FR-007**: 숫자는 천 단위 구분 기호와 `자` 단위를 붙여 한국어로 표시한다(MUST). 예: `공백 포함 1,234자 · 공백 제외 1,050자`.
- **FR-008**: 글을 열었을 때 이미 저장된 내용의 글자 수가 첫 화면부터 표시되어야 한다(MUST).
- **FR-009**: 글자 수 표시는 데스크톱과 모바일(360px 폭 이상) 모두에서 내용 입력을 가리거나 레이아웃을 깨뜨리지 않아야 한다(MUST).
- **FR-010**: 글자 수 표시는 보조 정보로서 내용보다 시각적으로 덜 두드러져야 하며, 입력 흐름(포커스, 커서 위치, 키보드 조작)을 방해하지 않아야 한다(MUST).
- **FR-011**: 화면 낭독기 사용자가 글자 수를 읽을 수 있어야 하지만, 입력할 때마다 숫자가 자동으로 낭독되어 입력을 방해해서는 안 된다(MUST).
- **FR-012**: 글자 수는 내용에서 계산되는 값이며 별도로 저장하지 않는다(MUST NOT). 기존 글 데이터의 형태는 바뀌지 않는다.

### Key Entities

- **글 내용 글자 수**: 글(제목·내용) 중 내용에서 계산되는 파생 값. 공백 포함 수와 공백 제외 수 두 가지가 있으며, 저장되지 않고 화면에 표시될 때마다 현재 내용으로부터 구한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 글자를 입력하거나 지운 뒤 글자 수가 바뀌기까지 체감 지연이 없다 (0.1초 이내).
- **SC-002**: 한글·영문·숫자·공백·줄바꿈·이모지가 섞인 검증용 예문 10개 모두에서 표시된 글자 수가 손으로 센 값과 100% 일치한다.
- **SC-003**: 5만 자 분량의 글에서도 입력 반응 속도가 글자 수 표시가 없을 때와 체감상 차이가 없다.
- **SC-004**: 분량을 확인하려고 내용을 다른 글자 수 세기 도구로 옮기는 일이 0회가 된다 (사용자 자가 점검).
- **SC-005**: 360px 폭 화면에서 글자 수 표시가 잘리거나 다른 요소와 겹치지 않는다.

## Assumptions

- 글자 수 표시는 글 상세(편집) 화면에만 둔다. 업무 목록의 글 카드·검색 결과에는 표시하지 않는다.
- 글자 수 제한(최대 글자 수 설정, 초과 경고)은 이번 범위에 포함하지 않는다. 표시만 한다.
- 단어 수·문장 수·원고지 매수·바이트 수 등 다른 분량 지표는 범위 밖이다.
- 공백 포함·제외 두 값의 문구와 배치, 강조 정도는 프로젝트 디자인 시스템(DESIGN.md)의 보조 텍스트 규칙을 따른다.
- 이 기능은 PRD의 Non-Goals(리치 에디터 등)에 해당하지 않으며, 기존 제목 + 텍스트 내용 구조를 그대로 유지한다.
- 계산은 기기 안에서 이뤄지며 외부 서비스나 추가 비용이 필요하지 않다.
