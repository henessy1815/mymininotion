# Feature Specification: 랜덤 고양이 커버 이미지

**Feature Branch**: `002-cat-cover-image`

**Created**: 2026-10-02

**Status**: Draft

**Input**: User description: "https://cataas.com/cat/cute 이 api를 사용해서 랜덤 고양이 사진을 받아올거야. 받아온 고양이 사진을 미니노션 제목입력창 위에 커버 이미지를 놓자. 위에 알려준 엔드포인트로 요청해서 보여주도록 하고, 로드되는 동안은 로딩 스피너 대신 스켈레톤ui에 시머효과를 줘서 처리해줘."

## Clarifications

### Session 2026-10-02

- Q: 같은 글을 다시 열면 같은 고양이를 보여 줄까요, 새 랜덤 고양이를 보여 줄까요? → A: 열 때마다 새 랜덤 고양이를 받아온다. 사진은 글에 저장하지 않으며 글 데이터 형태는 바뀌지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 글 상단에서 고양이 커버 보기 (Priority: P1)

사용자는 글 상세 화면을 열면 제목 입력칸 바로 위에 귀여운 고양이 사진이 커버 이미지로 놓인 것을
본다. 밋밋한 빈 화면 대신 글마다 시각적인 머리가 생겨, 기록을 시작할 때 기분이 가벼워지고 글
화면이 노션처럼 정돈되어 보인다.

**Why this priority**: 요청된 기능의 핵심이다. 이것만으로도 "제목 위 커버 이미지"라는 가치가 완성된다.

**Independent Test**: 아무 글이나 열어, 제목 입력칸 위에 고양이 사진이 나타나고 제목·내용 입력이
이전과 똑같이 동작하는지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 사용자가 글 목록에서 글 하나를 선택했을 때, **When** 글 상세 화면이 열리고 이미지 받기가 끝나면, **Then** 제목 입력칸 바로 위에 고양이 사진이 커버 영역 전체를 채워 보인다.
2. **Given** 커버 이미지가 표시된 상태, **When** 사용자가 제목이나 내용을 입력하면, **Then** 입력·자동 저장·글자 수 표시가 커버가 없을 때와 똑같이 동작한다.
3. **Given** 새 글(제목·내용이 모두 빈 글)을 막 만든 상태, **When** 화면이 열리면, **Then** 커버 영역이 표시되면서도 포커스는 여전히 제목 입력칸에 있어 바로 타이핑할 수 있다.
4. **Given** 세로로 긴 사진이나 가로로 긴 사진을 받았을 때, **When** 커버가 표시되면, **Then** 커버 영역의 높이는 항상 같고 사진은 비율을 유지한 채 영역을 채운다(찌그러지지 않는다).

---

### User Story 2 - 불러오는 동안 스켈레톤으로 자리 확인 (Priority: P2)

사진을 받아오는 동안 사용자는 빙글 도는 로딩 아이콘 대신, 커버와 같은 크기의 회색 자리표시
영역에 빛이 좌우로 지나가는 효과(시머)를 본다. 무엇이 어디에 나타날지 미리 알 수 있고, 사진이
도착해도 제목·내용이 아래로 밀려 내려가지 않는다.

**Why this priority**: 외부에서 사진을 받아오므로 지연은 반드시 생긴다. 이 처리가 없으면 화면이
덜컥 움직이고 빈 공간이 어색하게 보인다. 다만 P1이 없으면 의미가 없으므로 그다음 순위다.

**Independent Test**: 네트워크를 느리게 한 상태에서 글을 열어, 사진이 나타나기 전까지 커버 자리에
시머가 흐르는 스켈레톤이 보이고, 사진이 나타날 때 제목 입력칸의 위치가 변하지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사진을 아직 받는 중일 때, **When** 글 상세 화면이 표시되면, **Then** 커버 자리에 같은 크기의 스켈레톤이 보이고 그 위로 시머 효과가 반복해서 지나간다. 회전하는 로딩 아이콘은 보이지 않는다.
2. **Given** 스켈레톤이 보이는 상태, **When** 사진 받기가 끝나면, **Then** 스켈레톤이 사진으로 바뀌고 제목 입력칸의 화면상 위치는 바뀌지 않는다.
3. **Given** 스켈레톤이 보이는 상태, **When** 사용자가 제목이나 내용을 입력하면, **Then** 사진을 기다리지 않고 바로 입력된다.
4. **Given** 사용자의 기기가 "동작 줄이기" 설정을 켠 상태, **When** 스켈레톤이 보이면, **Then** 시머는 움직이지 않고 정적인 자리표시만 보인다.

---

### User Story 3 - 사진을 못 받아도 글쓰기는 그대로 (Priority: P3)

외부 사진 서비스가 느리거나 응답하지 않거나 오프라인일 때도, 사용자는 깨진 이미지 아이콘이나
끝없는 스켈레톤을 보지 않고 평소처럼 글을 쓴다.

**Why this priority**: 실패는 드물지만, 실패했을 때 글쓰기가 방해받으면 "데이터·기록 흐름 우선"
원칙을 해친다. 기능 자체의 가치보다는 안전망이므로 마지막 순위다.

**Independent Test**: 네트워크를 끊거나 사진 주소 요청을 막은 상태에서 글을 열어, 깨진 이미지 대신
정돈된 대체 커버가 보이고 제목·내용 입력이 정상인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사진 요청이 실패했을 때, **When** 실패가 확인되면, **Then** 스켈레톤이 멈추고 깨진 이미지 표시 없이 같은 크기의 단색 대체 커버가 보인다.
2. **Given** 사진 요청에 응답이 오지 않을 때, **When** 일정 시간(약 10초)이 지나면, **Then** 실패와 똑같이 대체 커버로 바뀌고 스켈레톤이 끝없이 돌지 않는다.
3. **Given** 사진을 받지 못한 상태, **When** 사용자가 제목·내용을 입력하면, **Then** 입력과 자동 저장이 정상 동작하며 저장 상태 표시에 사진 실패가 섞이지 않는다.

---

### Edge Cases

- 사진이 도착하기 전에 사용자가 다른 글로 이동하면, 이전 글의 사진이 새 글 화면에 나타나서는 안 된다.
- 같은 글을 나갔다가 다시 열면 새 랜덤 고양이 사진을 받아오며, 그동안 스켈레톤이 다시 보인다. 이전 사진과 같은 사진이 나와도 정상이다.
- 매우 큰 사진이 와도 커버 영역 크기는 고정이며 레이아웃이 깨지지 않는다.
- 360px 폭 모바일 화면에서도 커버가 화면 폭에 맞게 표시되고 제목 입력칸을 가리지 않는다.
- 다크 모드·라이트 모드 모두에서 스켈레톤과 대체 커버가 배경과 구분된다.
- 글 목록·검색 결과·사이드바 등 글 상세 외 화면에는 커버를 표시하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 글 상세 화면의 제목 입력칸 바로 위에 커버 영역을 표시해야 한다(MUST).
- **FR-002**: 시스템은 커버 영역에 사용자가 지정한 외부 고양이 사진 서비스에서 받은 랜덤 고양이 사진을 표시해야 한다(MUST).
- **FR-003**: 커버 영역은 사진 비율과 관계없이 고정된 높이를 가지며, 사진은 비율을 유지한 채 영역을 채워야 한다(MUST). 데스크톱과 모바일의 높이는 각각 일정해야 한다.
- **FR-004**: 사진을 받는 동안 시스템은 커버와 같은 크기의 스켈레톤 자리표시를 시머 효과와 함께 표시해야 하며, 회전형 로딩 아이콘을 쓰지 않아야 한다(MUST NOT).
- **FR-005**: 스켈레톤 → 사진 → 대체 커버의 전환 중 커버 영역의 크기는 변하지 않아야 하며, 제목·내용 영역이 밀려나는 레이아웃 이동이 없어야 한다(MUST).
- **FR-006**: 사진 요청이 실패하거나 약 10초 안에 완료되지 않으면, 시스템은 깨진 이미지 표시 없이 같은 크기의 단색 대체 커버를 표시해야 한다(MUST).
- **FR-007**: 커버 이미지의 로딩·실패 여부와 관계없이 제목·내용 입력, 자동 저장, 저장 상태 표시, 글자 수 표시는 기존과 동일하게 즉시 동작해야 한다(MUST).
- **FR-008**: 새 글을 열었을 때 제목 입력칸에 포커스가 가는 기존 동작을 유지해야 한다(MUST). 커버 영역은 키보드 탭 순서에 끼어들지 않아야 한다.
- **FR-009**: 커버 사진은 장식용으로 취급해 화면 낭독기가 읽지 않도록 해야 한다(MUST).
- **FR-010**: 사용자가 "동작 줄이기"를 설정한 경우 시머 애니메이션을 멈추고 정적 자리표시로 대체해야 한다(MUST).
- **FR-011**: 사진 요청이 진행 중일 때 다른 글로 이동하면, 이전 요청의 결과가 새 화면의 커버로 표시되지 않아야 한다(MUST).
- **FR-012**: 시스템은 글 상세 화면을 열 때마다 새 랜덤 고양이 사진을 요청해야 하며, 받은 사진을 글 데이터에 저장하지 않아야 한다(MUST NOT). 글의 저장 데이터 형태는 바뀌지 않는다.
- **FR-013**: 커버는 글 상세 화면에만 표시하며, 글 목록·검색 결과·사이드바에는 표시하지 않는다.

### Key Entities *(include if feature involves data)*

- **커버 이미지**: 글 상세 화면 상단에 놓이는 장식용 사진. 상태는 "불러오는 중 / 표시됨 / 실패(대체 커버)" 세 가지다. 글의 제목·내용과 독립적이며 저장되지 않는다(화면을 열 때마다 새로 받음). 커버 상태가 글의 저장에 영향을 주지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 일반적인 네트워크 환경에서 글을 열었을 때 10번 중 9번 이상 3초 안에 고양이 사진이 커버에 표시된다.
- **SC-002**: 스켈레톤이 사진이나 대체 커버로 바뀔 때 제목 입력칸의 화면상 위치 변화가 0이다 (레이아웃 이동 없음).
- **SC-003**: 사진 서비스가 응답하지 않는 상황에서도 글을 연 직후부터 제목·내용을 입력할 수 있고, 10초 안에 스켈레톤이 대체 커버로 바뀐다 (끝없는 로딩 0건).
- **SC-004**: 화면 어디에도 깨진 이미지 아이콘이 나타나는 경우가 0건이다.
- **SC-005**: 360px 폭 모바일과 데스크톱 모두에서 커버가 제목 입력칸을 가리거나 가로 스크롤을 만드는 경우가 0건이다.
- **SC-006**: 커버 추가 전후로 새 글 생성 → 제목 입력 시작까지의 키보드 조작 횟수가 늘지 않는다.

## Assumptions

- 사진 출처는 사용자가 지정한 공개 고양이 사진 서비스의 "cute" 랜덤 사진 주소(`https://cataas.com/cat/cute`)이며, 무료·무인증으로 사용할 수 있어 0원 운영 원칙에 맞는다. 이 서비스의 가용성은 우리가 통제할 수 없으므로 실패 처리(US3)를 필수로 둔다.
- 커버는 장식용 단일 이미지이며, PRD Non-Goal의 "이미지 블록"(본문 안에 사진을 넣는 리치 에디터 기능)에 해당하지 않는다. 사용자가 직접 사진을 올리거나 다른 사진을 고르는 기능, 커버 위치 조정, 커버 끄기, 같은 화면에서 다른 고양이로 바꾸기 기능은 이번 범위에 포함하지 않는다.
- 커버 높이는 노션의 일반적인 커버 비율을 참고해 데스크톱 약 200px, 모바일은 그보다 낮은 고정값으로 정하며, 정확한 값은 디자인 시스템 토큰으로 plan 단계에서 결정한다.
- 대체 커버는 문구나 재시도 버튼 없이 디자인 시스템의 중립 배경색 한 가지로 채운다. 커버는 장식이므로 실패를 오류 메시지로 알리지 않는다.
- 시간 제한 약 10초는 일반적인 웹 이미지 로딩 기대치를 기준으로 한 기본값이다.
- 시머 효과·스켈레톤은 현재 디자인 시스템에 없는 새 패턴이므로, 구현 시 토큰·컴포넌트를 추가하고 DESIGN.md를 함께 갱신한다.
